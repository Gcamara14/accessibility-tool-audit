Platform Unification

One codebase, two deployments, US as the authoritative baseline. Merge the divergent intl-ssaeim RFID fork back onto the SSAEIM (us/) tree and serve US + 8 international markets from a single binary — country flows through the code as data, not as a build profile.

Executive Summary

The US and International RFID stacks drifted into two separate forks (org SSAEIM vs intl-ssaeim). A code-level comparison of all 9 shared repos confirmed the divergence is real but convergeable: the base Java packages are identical, and the deltas cluster around three axes that don't exist in US — multi-country tenancy (Canada live, Mexico scaffolded), a Sam's-Club "Banner" dimension, and CCM2 + Akeyless + mTLS plumbing. The plan adopts US as the authoritative base (D13), freezes the INTL tree as a source of features to absorb, and routes by country at the edge so one binary serves both regions.

Top-line

This is a forward-merge, not a green-field rewrite. US absorbs the few genuinely-new INTL capabilities (country-keyed config, EI bootstrap topology, fr-CA locale, per-country IQS headers) behind clean abstractions, with security staying aligned to the US baseline. Sam's Club and RFID 1.0 are out of scope; in-code multi-tenancy is deferred behind a deploy-time market list until upstream/downstream systems support it.

1. Team Context & Objectives

Domain & surface

Store RFID 2.0 — the platform behind VizPick Fashion binning, Find-with-RFID, scan ingestion and EI on-hand updates. Surface under review: 9 backend services (store-rfid-service, -commons, -event-manager, -pre-scan, -post-scan, -scan-api, rfid-batch) and 2 apps (rfid-scan-mini-app, native-rfid-scanner), each with a divergent INTL twin.

Workshop scope

  • Discover what differs between US and INTL, and whether it needs to differ.
  • Decide the architecture (US baseline, country routing) and log every call (D1–D44).
  • Plan a concrete, estimated execution path to a single codebase.
  • Out of scope: Sam's Club banner, RFID 1.0, cluster consolidation (D20), in-code multi-tenancy.

2. Approach & Ways of Working

How AI was leveraged

  • Mechanical diff at scale: all 9 repo pairs diffed (~169k lines), then de-noised — e.g. CRLF inflation in store-rfid-service (41k→22k real lines).
  • Cited evidence, no vibes: every claim backed by a quoted diff line or path; sub-agents read each diff in full and produced per-repo reports.
  • Cross-validation: findings re-checked with independent greps (geo flags, Spring Boot versions, Sam's presence, Find-It folding).

Decision-making

  • Decision log as single source of truth — 44 decisions (D1–D44), each Decided / Deferred / Out-of-scope.
  • Two ADRs: Backend (service-mesh routing) and UI (mini-app globalization).
  • US-baseline rule (D13): all changes land in us/; INTL is frozen reference.

How work was organized

  • 36 tasks collapsed onto 7 parallel rails / 16 groups; anything without a dependency arrow can start day one.
  • T-shirt sizing → person-weeks (XS .1 / S .3 / M .8 / L 1.5 / XL 3.0).
  • Investigations (location MDM, fashion groupings, open-scan) run off the critical path with their own owners.

3.2 Key architectural decisions

Tenancy & routing

Country is data, not a profile. Edge derives it once from X-Country-Code (or path); every layer reads from request scope. Missing/malformed → HTTP 400, never a silent US default (D3, D7, D22, D28).

Config & secrets

New US-owned store-rfid-v2-ccm repo with per-app ccm/ folders; INTL deltas live in a zone override. One Akeyless config, zone-interpolated, with cross-region guardrails (D4, D9, D18, D19, D40).

Adapters (sources / sinks)

Eight SPIs in commons — IQS, MELO, Location/MDM, store-list, secrets, Kafka topic, Kafka broker, feature-toggle — each a registry bean reading country-keyed CCM. No if (country=="US") in core.

Deliberately dropped

Sam's banner & Pete adapter, RFID 1.0 legacy paths, INTL frontend apps. Cluster consolidation & Dynatrace explicitly out of scope (D15, D20).

3.3 What worked — and what created friction

Worked better than expected
  • Architecture was already externalized — mini-app reads base URLs/country from CCM + URL path; "the repo is in a good position."
  • Base Java packages identical across forks — this is a merge, not a rewrite.
  • AI diff-then-cite gave an evidence-backed gap analysis in hours, not weeks.
  • Decision log (D1–D44) collapsed ambiguity into unambiguous direction.
Friction points
  • Cassandra PK change = backfill (dual-write → backfill → cutover), not an in-place ALTER (D39) — the single largest risk.
  • API-Proxy externalization is cross-team (security review, new environment + subscription) and gates service-mesh header routing (D41, D7).
  • INTL investigations — location MDM globalized view, fashion groupings, open-scan availability — gate the INTL rollout (D34, D37, D38).
  • Estimate reconciliation: figures revised 490 → 154 → 32 weeks as scope tightened — now anchored to the 32-week program-tracker LOE.

UI ADR — rfid-scan-mini-app globalization

NEW vs SA READOUT

Source: Confluence rfid-scan-mini-app / RFID UI ADR · RFIDSI-4315. The points below are taken directly from that ADR.

Goal: Enable rfid-scan-mini-app (@walmart/rfid-scan-mini-app) to support countries beyond the US (e.g., Mexico, Canada) and additional locales beyond en-US / es-MX (specific locales TBD).

TL;DR: The repo is in a good position. The architecture is mostly externalized.

What is already globalization-ready
  • URL builder already injects a country code segment: /country/{countryCode}/store/{siteId}{endpoint}.
  • Country code is sourced from Redux (UserSelectors.getCountryCode), populated by the host app.
  • Base URLs and consumer IDs are read from CCM via ConfigSelectors (getInventoryBaseUrl, getDistancingBaseUrl, getRfidUrls, getRfidConsumerIds) — the hardcoded DEFAULT_* constants in source are fallback values only, used when CCM returns null. Pointing the app at a non-US backend is a CCM change, not a code change.
  • i18next is wired up via @walmart/allspark-foundation and supports per-locale translation files.
  • Most RFID thresholds, wand power profiles, and timing values are driven by ConfigSelectors / CCM, not constants.
What is not yet globalization-ready
  • Only en-US and es-MX translation files exist.
  • The DEFAULT_MANUAL_REASON_CONFIG constant contains inline bilingual strings (en-US + es-MX) rather than translation keys.
  • Limited date / time localization.

One codebase, per-market options via CCM

How the front end serves multiple markets from the same build: country comes from the request / Redux, and CCM supplies the per-market options at runtime. This is the same mechanism that lets the single artifact scale toward multi-tenancy — adding a market is a CCM change, not a code change.

5. Recommendations to Scale + Continue

Repeat

  • AI diff-then-cite as the gap-analysis backbone — mechanical, evidence-first.
  • US-baseline + frozen-INTL-as-source — removes "whose code wins" debate.
  • Decision log as the single source of truth (44 calls, each with status).
  • SPI/registry abstraction for every source/sink that differs by country.

Do differently

  • Clear Phase 0 day-1 blockers first — SIRO RSA key rotation, INTL Akeyless path, and the MARKETS market-config contract — before merge work starts.
  • Lock product decisions earlier (Find-It disposition, open-scan per market, fashion groupings).
  • Pin the service-mesh failure-mode default early — Backend ADR leaves default-to-US vs 400 vs reject as TBD.
  • Maintain one canonical estimate tracker anchored to the 32-week program LOE.

Org improvements

  • Unblock external deps: API-Proxy env/subscription, DCS-W onboarding, INTL Akeyless zones, SIRO key rotation.
  • Get product decisions on the in/out-of-scope grey areas before Phase 1 exits.
  • Drift control: Sentinel-style PR gate + a runtime arm comparing deployed config to a tenant manifest.
  • Per-country observability ownership — who owns the unified dashboard (D15 TBD).
Closing executive insight

The expensive part of globalization here isn't the code — it's the decisions and the dependencies. The architecture is already externalized, the forks share a common ancestor, and AI compressed the gap analysis from weeks to hours. With US as the baseline and country flowing through the stack as data, the core unification is a 32-week effort (~8–11 calendar weeks at 3–4 engineers) — gated mostly by external platform enablement (API Proxy, Akeyless, DCS-W) and a handful of product calls. Land Phase 1 cleanly and the same playbook generalizes to the next banner and the next market.
