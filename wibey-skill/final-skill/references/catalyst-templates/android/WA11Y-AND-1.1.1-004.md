**Template ID:** `WA11Y-AND-1.1.1-004`
**Platform:** Android
**WCAG Criterion:** 1.1.1 Non-text Content
**Jira Label:** `WA11Y-AND-1.1.1-004`
**Source Tickets:** CEPG-375973
**Source PRs:** [walmart-glass #139559](https://gecgithub01.walmart.com/Walmart-Android/walmart-glass/pull/139559)
**Date Ingested:** 2026-05-07

## 🛑 The Problem

A **complex image** — a product infographic, comparison chart, nutrition facts table, or AI-generated product feature summary — carries **more information than a simple `contentDescription` label can convey**. TalkBack announces only a one-liner (e.g., "Product image") or nothing at all. Screen-reader users have no way to access the data encoded in the image: ingredient breakdowns, feature comparisons, dimensions, nutritional values.

Two failure modes:
1. A product infographic image has the same generic `contentDescription` as any other product photo — TalkBack treats a dense feature-summary image identically to a plain photo.
2. An AI-generated product infographic (`INFO_PRODUCT_IMAGE`) has no accessible disclosure that its content is AI-generated, and no pointer to where the same data is available in accessible text form.

**Symptom (Jira):** "TalkBack user can't access product feature chart", "Infographic not described to screen reader", "AI-generated product image has no meaningful alt text", "Screen reader reads generic 'product image' for complex visual".

---

## ✅ The Fix Pattern

### Pattern A: Brief description + pointer to structured data

The WCAG pattern for complex images is: provide a concise description of what the image *is*, then **point to where the full accessible data lives** as nearby text or a structured section of the page.

**❌ Bad Code:**
```kotlin
// Product infographic — same generic alt text as a plain product photo.
// TalkBack: "Product image" — user gets no indication of what data is inside.
binding.productImage.contentDescription = product.name
```

**✅ Good Code:**
```kotlin
// Set a description that (1) identifies the image type and (2) directs the user
// to the structured text where the same data is accessible.
binding.productImage.contentDescription = string(
    R.string.item_infographic_carousel_ada,
    LocalizedStringKeys.ITEM_NAME to product.name
)
// → "Infographic summarizing the features of Great Value Whole Milk 1 Gallon.
//    Data is provided in the Key item features section Below."
```

```xml
<!-- strings.xml — two variants: one for the carousel, one for the full gallery -->
<string name="item_infographic_carousel_ada">
    Infographic summarizing the features of {itemName}.
    Data is provided in the Key item features section Below.
</string>
<string name="item_infographic_gallery_ada">
    Infographic summarizing the features of {itemName}.
    Data is provided in the Key item features section on the main item page.
</string>
```

The key structure: **"[Image type] summarizing [content]. [Equivalent data] is available in [location]."**

---

### Pattern B: AI-generated image — disclosure + info button

When a product image is AI-generated (`INFO_PRODUCT_IMAGE` media type), surface a "Generated by AI" label and a tappable info button whose `contentDescription` names the disclosure:

**✅ Good Code:**
```kotlin
/**
 * Shows the GenAI indicator (label + info icon) only for INFO_PRODUCT_IMAGE media.
 * The info button's contentDescription is set from a string resource that includes
 * the product name, so TalkBack says e.g.
 * "Infographic summarizing the features of [product]. Data is provided in Key item features. Info"
 */
fun setupGenAIIndicator(
    indicatorText: TextView,
    infoButton: View,
    mediaType: String?,
    itemName: String,
    @StringRes contentDescriptionRes: Int,
    onInfoClicked: () -> Unit
) {
    val isInfoProductImage = mediaType == INFO_PRODUCT_IMAGE
    indicatorText.isVisible = isInfoProductImage
    infoButton.isVisible = isInfoProductImage
    if (isInfoProductImage) {
        infoButton.contentDescription = string(contentDescriptionRes, "itemName" to itemName)
        infoButton.setOnClickListener { onInfoClicked() }
    }
}
```

Call site in the carousel adapter:
```kotlin
// Carousel (PDP image carousel)
setupGenAIIndicator(
    indicatorText = binding.genAiIndicatorText,
    infoButton = binding.genAiInfoButton,
    mediaType = media?.type,
    itemName = genAIIndicatorMetaData?.itemName.orEmpty(),
    contentDescriptionRes = R.string.item_infographic_carousel_ada,
    onInfoClicked = { buttonListener?.onGenAIInfoClicked() }
)

// Gallery (full-screen image gallery)
setupGenAIIndicator(
    indicatorText = binding.genAiIndicatorText,
    infoButton = binding.genAiInfoButton,
    mediaType = item.type,
    itemName = itemName,
    contentDescriptionRes = R.string.item_infographic_gallery_ada,
    onInfoClicked = { onGenAIInfoClicked?.invoke() }
)
```

XML layout for the overlay elements:
```xml
<!-- "Generated by AI" text label -->
<TextView
    android:id="@+id/gen_ai_indicator_text"
    android:contentDescription="@string/item_reviews_generated_by_ai"
    android:text="@string/item_reviews_generated_by_ai"
    android:visibility="gone" />

<!-- Info disclosure button -->
<ImageView
    android:id="@+id/gen_ai_info_button"
    android:contentDescription="@string/item_generated_by_ai_disclaimer"
    android:importantForAccessibility="yes"
    android:src="@drawable/ld_ic_info_circle"
    android:visibility="gone" />
```

```xml
<!-- strings.xml -->
<string name="item_reviews_generated_by_ai">Generated by AI</string>
<string name="item_generated_by_ai_disclaimer">Generated by AI, Disclosure and Disclaimer</string>
```

### Pattern C: Alt text from API data model

For images where the backend supplies an `alt` field (CMS-authored or data-driven descriptions), wire the `alt` text through the data model all the way to `contentDescription`:

```kotlin
// Data model — carry alt text alongside the image URL
data class ImageDetails(
    val src: String,
    val alt: String?
)

// ✅ Use API-provided alt text as contentDescription
binding.badgeImage.contentDescription = imageDetails.alt
// Only falls back if alt is blank or null — in that case treat as decorative
if (imageDetails.alt.isNullOrBlank()) {
    binding.badgeImage.importantForAccessibility = View.IMPORTANT_FOR_ACCESSIBILITY_NO
}
```

## 🔑 Key Rules

- **A complex image needs two things: a brief description AND a pointer to the full data** — "Infographic summarizing the features of [product]. Data is provided in the Key item features section below." gives TalkBack users both context and a navigation destination.
- **"Complex image" = any image where visual content carries more meaning than its label** — product infographics, comparison charts, nutrition facts tables rendered as images, and AI-generated product summaries all qualify. A plain product photo does not.
- **Always name the image type** ("Infographic", "Chart", "Comparison table") — this tells the user what they're looking at before describing it. "Product image" is never enough for a complex image.
- **Point to structured accessible text** — the same data in the image should be available as real text somewhere on the page (Key features section, description, data table). Reference that location explicitly in the alt description.
- **AI-generated images need a disclosure** — add a labelled info button (`contentDescription = "Generated by AI, Disclosure and Disclaimer"`) so TalkBack users know the image content was created by AI, matching FTC and Walmart disclosure requirements.
- **Wire `alt` from the API** — if the backend provides an `alt` field for images, propagate it through the data model to `contentDescription`. Never discard alt text data returned from the API.

---

## ⚠️ WCAG Failure Without This Fix

- **1.1.1 (Non-text Content):** All non-text content that is presented to the user must have a text alternative that serves an equivalent purpose. A product infographic image with a one-word label ("image") or a generic product name fails to serve the equivalent purpose — a sighted user can scan the feature highlights visually while a TalkBack user receives no access to the same data. Complex images require descriptions whose detail matches the informational density of the image itself.
