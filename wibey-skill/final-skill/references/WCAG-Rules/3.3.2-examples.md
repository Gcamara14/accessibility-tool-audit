# 3.3.2 Labels or Instructions - Pass/Fail Examples

*(No examples documented yet. When the AI fixes a bug related to this rule, it will document the unique fix pattern here!)*

## Example: Empty label element

**What failed**: A label associated with an input must contain text so screen reader users know what the field is for.

**Bad Code**:
```html
<form><label for="empty"></label>
<input id="empty" type="text" value="" /></form>
```

**How it was fixed**: Applied the correct fix based on the component type.

**Corrected Code**:
```html
<form><label for="empty">Enter text</label>
<input id="empty" type="text" value="" /></form>
```

## Example: Missing labels on multi-part inputs (Date of Birth)

**What failed**: Even if a visual label is clumsy, every input must have a programmatic accessible name. Visually hidden labels solve this.

**Bad Code**:
```html
<input id="missing-labels-month" type="text"/>
<input id="missing-labels-year" type="text"/>
```

**How it was fixed**: Applied the correct semantic fix.

**Corrected Code**:
```html
<label for="missing-labels-month" class="visually-hidden">Month</label>
<input id="missing-labels-month" type="text"/>
<label for="missing-labels-year" class="visually-hidden">Year</label>
<input id="missing-labels-year" type="text"/>
```

## Example: Forms error messages no suggestion for corrections given e.g. required format

**What failed**: Form fields require associated labels.

**Bad Code**:
```html
<input class="has-errors" pattern="7[0-9]{9}" required="" type="tel"/>
```

**How it was fixed**: Applied semantic HTML rule.

**Corrected Code**:
```html
<input class="has-errors" pattern="7[0-9]{9}" required="" type="tel"/ aria-label="Input field">
```
