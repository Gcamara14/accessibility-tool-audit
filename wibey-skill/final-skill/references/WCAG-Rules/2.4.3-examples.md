# 2.4.3 Focus Order - Pass/Fail Examples

## Web Examples

### Example: Positive tabindex used

**What failed**: Using tabindex > 0 overrides the natural reading/focus order of the page, causing a confusing experience for keyboard users.

**Bad Code**:
```html
<a href="page.html" tabindex="5">A link with a tabindex greater than 0</a>
```

**How it was fixed**: Removed the positive tabindex so the element follows the natural DOM order.

**Corrected Code**:
```html
<a href="page.html">A link with a tabindex greater than 0</a>
```

## iOS Examples

### Example: VoiceOver focus jumps to top after collection view update (COMM-1808)

**What failed**: `WCPImageUploader` calls `reloadData()` after adding or removing a photo. This destroys all `UICollectionView` cells and reconstructs them, causing VoiceOver to lose its focus anchor and jump to the top of the screen. Users who rely on VoiceOver lose their place after every image operation.

**Template:** [`WA11Y-IOS-2.4.3-001`](../catalyst-templates/ios/WA11Y-IOS-2.4.3-001.md)

#### Pattern A: Adding an image

**Bad Code**:
```swift
public func addImage(imageModel: ImageModel) {
    uploadedImages.append(imageModel)
    updateCollectionViewState()
    reloadThumbnails()  // reloadData() — destroys VoiceOver focus
}
```

**How it was fixed**: Replaced `reloadData()` with `performBatchUpdates()` using state-machine transition logic, then posted `UIAccessibility.layoutChanged` targeting the newly added cell.

**Corrected Code**:
```swift
public func addImage(imageModel: ImageModel) {
    let previousState = state
    uploadedImages.append(imageModel)
    updateCollectionViewState()

    let newImageIndex = IndexPath(item: uploadedImages.count - 1, section: 0)

    collectionView.performBatchUpdates({
        switch (previousState, state) {
        case (.empty, .add), (.add, .add):
            collectionView.insertItems(at: [newImageIndex])
        case (.empty, .limitReached), (.add, .limitReached):
            collectionView.reloadItems(at: [newImageIndex])
        default:
            break
        }
    }, completion: { [weak self] _ in
        guard let self else { return }
        updateCollectionViewHeight()
        UIAccessibility.post(
            notification: .layoutChanged,
            argument: collectionView.cellForItem(at: newImageIndex)
        )
    })
}
```

#### Pattern B: Removing an image (focus nearest remaining cell)

**Bad Code**:
```swift
private func removeImage(at index: Int) {
    guard let image = uploadedImages[safe: index] else { return }
    delegate?.removeImageClicked(image)
    uploadedImages.remove(at: index)
    updateCollectionViewState()
    reloadThumbnails()  // reloadData() — destroys VoiceOver focus
}
```

**How it was fixed**: Used `performBatchUpdates()` with state-aware delete/insert logic, then focused VoiceOver on the nearest remaining thumbnail or the "Add" button if empty.

**Corrected Code**:
```swift
private func removeImage(at index: Int) {
    guard let image = uploadedImages[safe: index] else { return }
    delegate?.removeImageClicked(image)

    let previousState = state
    uploadedImages.remove(at: index)
    updateCollectionViewState()

    let removedIndexPath = IndexPath(item: index, section: 0)

    collectionView.performBatchUpdates({
        switch (previousState, state) {
        case (.add, .add), (.add, .empty):
            collectionView.deleteItems(at: [removedIndexPath])
        case (.limitReached, .add):
            collectionView.deleteItems(at: [removedIndexPath])
            collectionView.insertItems(at: [IndexPath(item: uploadedImages.count, section: 0)])
        case (.limitReached, .empty):
            collectionView.reloadItems(at: [removedIndexPath])
        default:
            break
        }
    }, completion: { [weak self] _ in
        guard let self else { return }
        updateCollectionViewHeight()

        let focusIndex: IndexPath
        if uploadedImages.isEmpty {
            focusIndex = IndexPath(item: 0, section: 0) // "Add" button
        } else {
            let clamped = min(index, uploadedImages.count - 1)
            focusIndex = IndexPath(item: clamped, section: 0)
        }
        UIAccessibility.post(
            notification: .layoutChanged,
            argument: collectionView.cellForItem(at: focusIndex)
        )
    })
}
```

#### Pattern C: Testable focus abstraction (protocol injection)

**How it was fixed**: Extracted `UIAccessibility.post` behind a protocol so unit tests can verify focus targets without a live VoiceOver runtime.

**Corrected Code**:
```swift
protocol AccessibilityFocusPosting {
    func postLayoutChanged(focusingCellAt indexPath: IndexPath,
                           in collectionView: UICollectionView)
}

private struct DefaultAccessibilityFocusPoster: AccessibilityFocusPosting {
    func postLayoutChanged(focusingCellAt indexPath: IndexPath,
                           in collectionView: UICollectionView) {
        UIAccessibility.post(
            notification: .layoutChanged,
            argument: collectionView.cellForItem(at: indexPath)
        )
    }
}

// Test spy:
final class MockAccessibilityFocusPoster: AccessibilityFocusPosting {
    var postedIndexPaths: [IndexPath] = []
    func postLayoutChanged(focusingCellAt indexPath: IndexPath,
                           in collectionView: UICollectionView) {
        postedIndexPaths.append(indexPath)
    }
}
```

#### Pattern D: Dismiss modal before mutating collection view

**What failed**: Calling `addImage()` while the image picker is still animating its dismissal causes a race condition with `performBatchUpdates()`.

**Bad Code**:
```swift
imageUploader.addImage(imageModel: selectedImageModel)
picker.dismiss(animated: true, completion: nil)
```

**Corrected Code**:
```swift
picker.dismiss(animated: true) { [weak self] in
    self?.imageUploader.addImage(imageModel: selectedImageModel)
}
```

### Example: Edit button skipped on repeated nudge updates + CTA focus trap (PGSPHARM-55747)

**Feature:** Pharmacy RX Amends — nudge card after adding RX item to basket
**Ticket:** PGSPHARM-55747 / PR #140485
**Template:** [`WA11Y-IOS-2.4.3-002`](../catalyst-templates/ios/WA11Y-IOS-2.4.3-002.md)

**What failed (two bugs):**
1. Edit button was reachable by VoiceOver on the first nudge appearance. On every subsequent add, the nudge updated in-place but Edit was silently skipped — no `UIAccessibility.post(.layoutChanged)` posted after `configure()`.
2. A `UIView` container wrapping Edit + Add to Order had `isAccessibilityElement = true` — this trapped VoiceOver in a cycle between the two CTAs, blocking forward/backward navigation.

**Bad Code:**
```swift
// Container wraps both CTAs and has isAccessibilityElement = true → trap
ctaContainerView.isAccessibilityElement = true

// configure() never signals a layout change → tree goes stale
func updateNudge(with items: [RxItem]) {
    configure(with: items)
    // ❌ no UIAccessibility.post() here
}
```

**How it was fixed:** Set `isAccessibilityElement = false` on the container, defined explicit `accessibilityElements` array with the correct reading order, and posted `.layoutChanged` targeting `editButton` after each update.

**Corrected Code:**
```swift
// 1. Container no longer captures focus
ctaContainerView.isAccessibilityElement = false

// 2. Explicit reading order on the nudge root view
accessibilityElements = [headingLabel, closeButton, thumbnailScrollView, editButton, addToOrderButton]

// 3. Refresh accessibility tree after every content update
func updateNudge(with items: [RxItem]) {
    configure(with: items)
    accessibilityElements = [headingLabel, closeButton, thumbnailScrollView, editButton, addToOrderButton]
    UIAccessibility.post(notification: .layoutChanged, argument: editButton)
    // VoiceOver re-evaluates tree; Edit button now reachable every time ✅
}
```

### iOS Key Signals

Look for these patterns when triaging iOS 2.4.3 focus bugs:
- `reloadData()` called after inserting/removing items in `UICollectionView` or `UITableView`
- VoiceOver focus "jumps to top" or "resets" after a user action
- `UIAccessibility.post(notification: .layoutChanged, argument: nil)` — posting with `nil` (should target a specific element)
- Missing `performBatchUpdates()` where incremental changes are possible
- Image uploaders, photo pickers, cart item lists, or any dynamic list with add/remove
