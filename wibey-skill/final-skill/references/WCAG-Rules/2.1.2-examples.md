# 2.1.2 No Keyboard Trap - Pass/Fail Examples

## iOS Examples

### Example: VoiceOver focus trapped between "Service hours" and "Holiday Hours" on Store details page (CEPG-341947)

**What failed:** On the Store details bottom sheet (Services → Find a Store → Store details), swiping right with VoiceOver past the "Service hours" section caused focus to loop back. Further swipes did not advance past "Holiday Hours" — the user was permanently trapped in that region and could not access any content beyond it.
**Template:** [`WA11Y-IOS-2.1.2-001`](../catalyst-templates/ios/WA11Y-IOS-2.1.2-001.md) — Var 1
**Source PR:** [#145371](https://gecgithub01.walmart.com/walmart-ios/glass-app/pull/145371)

**Root Cause (real):** `storeHourList.subAccessibilityElements` — a custom `[UIView]` property holding the `HourView` row instances — was not reset in `StoreDetailsCell.prepareForReuse()`. After UITableView cell recycling, VoiceOver retained stale hour-row references alongside newly populated rows, causing traversal to loop between phantom and real elements.

**Bad Code (`StoreDetailsCell.swift`):**
```swift
// ❌ prepareForReuse() does not clear subAccessibilityElements
override func prepareForReuse() {
    super.prepareForReuse()
    heading = nil
    model = nil
    // Missing: storeHourList.subAccessibilityElements = []
    // Stale HourView instances remain → VoiceOver loops between Service hours / Holiday Hours rows
}
```

**Corrected Code:**
```swift
// ✅ Clear stale accessibility element array before cell is reused
override func prepareForReuse() {
    super.prepareForReuse()
    heading = nil
    model = nil
    storeHourList.subAccessibilityElements = []  // ✅ VoiceOver tree is clean for the next cell's data
}
```

### Example: Backward VoiceOver navigation trapped on last soft bundle tile — Frequently Bought Together (CEPG-341972)

**What failed:** On the Item Page, a user tapped "View details" on a Frequently Bought Together bundle offer, then swiped right with VoiceOver through all soft bundle tile cards. On swiping left to navigate backward, focus was permanently trapped on the last bundle tile — further left swipes did nothing.
**Template:** [`WA11Y-IOS-2.1.2-001`](../catalyst-templates/ios/WA11Y-IOS-2.1.2-001.md) — Var 2
**Source PR:** [#156713](https://gecgithub01.walmart.com/walmart-ios/glass-app/pull/156713)

**Root Cause (real):** Two compounding issues in `ItemDetails/Sections/SoftBundle/`:
1. `SoftBundleItemVerticalTileContainerView` set `accessibilityElements = [stackView]` — wrapping tile views in a 4-level nested accessibility hierarchy. Backward VoiceOver traversal could not exit the stackView layer.
2. `SoftBundleItemVerticalTileView` exposed `productTitle`, `primaryPriceLabel`, `secondaryPriceLabel` as individual `isAccessibilityElement = true` nodes — VoiceOver cycled within a single tile and never advanced to the adjacent tile.

**Bad Code:**
```swift
// SoftBundleItemVerticalTileContainerView.swift
private func updateAccessibility() {
    isAccessibilityElement = false
    stackView.isAccessibilityElement = false
    accessibilityElements = [stackView]  // ❌ 4-level nesting — backward swipe trapped on last tile
}

// SoftBundleItemVerticalTileView.swift
primaryPriceLabel.isAccessibilityElement = true    // ❌ exposes sub-elements separately
secondaryPriceLabel.isAccessibilityElement = true  // ❌
productTitle.isAccessibilityElement = true         // ❌
containerView.isAccessibilityElement = false       // ❌ container hidden — VoiceOver cycles inside tile
```

**Corrected Code:**
```swift
// SoftBundleItemVerticalTileContainerView.swift
private func updateAccessibility() {
    isAccessibilityElement = false
    stackView.isAccessibilityElement = false
    accessibilityElements = stackView.accessibilityElements  // ✅ flatten — tile views exposed directly
}

// SoftBundleItemVerticalTileView.swift
// (removed individual isAccessibilityElement = true for sub-labels)
containerView.isAccessibilityElement = true        // ✅ one VoiceOver stop per tile
containerView.accessibilityLabel = accessibilityText  // composed: name + prices + ratings
containerView.accessibilityTraits = .button
```

**Key distinction from Var 1:** Var 1 (store details cell reuse) trapped traversal via stale accessibility element arrays from UITableViewCell recycling. Var 2 (bundle tiles) trapped via deep accessibility hierarchy nesting + sub-element exposure within a single tile. Different mechanisms, same WCAG 2.1.2 failure.
