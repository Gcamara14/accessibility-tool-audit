## Example: Image button with empty alt attribute

**What failed**: An input of type "image" must have a descriptive alt attribute, otherwise screen readers just announce "button" or the filename.

**Bad Code**:
```html
<input alt="" src="../assets/test_images/submit.png" type="image" />
```

**How it was fixed**: Applied the correct fix based on the component type.

**Corrected Code**:
```html
<input alt="Submit" src="../assets/test_images/submit.png" type="image" />
```

## Example: Image completely missing alt attribute

**What failed**: All images must have an alt attribute. If decorative, it should be empty (alt=""). If informative, it needs a description.

**Bad Code**:
```html
<img src="../assets/test_images/bbc-blocks-dark.png"/>
```

**How it was fixed**: Applied the correct fix based on the component type.

**Corrected Code**:
```html
<img src="../assets/test_images/bbc-blocks-dark.png" alt="BBC Blocks Logo"/>
```

## iOS Examples

### Example: Informative banner image skipped by VoiceOver (CEPG-343560)

**What failed:** A `WCPImageView` inside the OnePay Later promotional banner carried no `accessibilityLabel` and its parent container set `isAccessibilityElement = true` without a label, causing VoiceOver to skip all promotional text rendered in or on the image.
**Template:** [`WA11Y-IOS-1.1.1-001`](../catalyst-templates/ios/WA11Y-IOS-1.1.1-001.md)

**Bad Code:**
```swift
bannerImageView.isAccessibilityElement = false  // or omitted entirely
// parent: isAccessibilityElement = true, accessibilityLabel = nil
```

**How it was fixed:** Marked the image view as an accessibility element, set a combined `accessibilityLabel`, and ensured the parent container was not itself an opaque accessibility element.

**Corrected Code:**
```swift
bannerImageView.isAccessibilityElement = true
bannerImageView.accessibilityLabel = "OnePay Later promotion: Buy now, pay later with OnePay."
containerView.isAccessibilityElement = false
containerView.accessibilityElements = [bannerImageView]
```

### Example: Informative subscription image skipped (`accessibilityHidden` on informative image) (CRUISE-16235)

**What failed:** A SwiftUI `Image` on the Walmart+ "View Subscriptions" screen was marked `.accessibilityHidden(true)`. The image conveys subscription status — it is informative, not decorative. VoiceOver skipped it entirely.
**Template:** [`WA11Y-IOS-1.1.1-001`](../catalyst-templates/ios/WA11Y-IOS-1.1.1-001.md)

**Bad Code:**
```swift
Image("view-subscriptions-graphic")
    .accessibilityHidden(true)
```

**How it was fixed:** Removed `.accessibilityHidden(true)` and added `.accessibilityLabel(Text(...))`.

**Corrected Code:**
```swift
// SwiftUI
Image("view-subscriptions-graphic")
    .accessibilityLabel(Text("Your active subscriptions overview"))

// UIKit
imageView.isAccessibilityElement = true
imageView.accessibilityLabel = NSLocalizedString(
    "Your active Walmart+ subscriptions",
    comment: "Accessibility label for subscription overview graphic"
)
```

### Example: Image + text caption split into two accessibility elements (CRUISE-16210)

**What failed:** On the "My Subscriptions" screen, a payment card brand `UIImageView` and a "card ending in 1111" `UILabel` were separate accessibility elements. VoiceOver announced the image as its filename, then the label text in isolation — no semantic connection.
**Template:** [`WA11Y-IOS-1.1.1-001`](../catalyst-templates/ios/WA11Y-IOS-1.1.1-001.md)

**Bad Code:**
```swift
cardImageView.isAccessibilityElement = true   // no accessibilityLabel set
captionLabel.isAccessibilityElement = true    // reads "card ending in 1111" alone
```

**How it was fixed:** Container view made the single accessibility element with a combined `accessibilityLabel`.

**Corrected Code:**
```swift
cardContainerView.isAccessibilityElement = true
cardContainerView.accessibilityLabel = "Visa card ending in 1111"
cardContainerView.accessibilityTraits = .image
cardImageView.isAccessibilityElement = false
captionLabel.isAccessibilityElement = false
```
