# 4.1.2 Name, Role, Value - Pass/Fail Examples

## iOS Examples

### Example: Custom tappable UIView missing .button accessibility trait (CEPG-340598)

**What failed:** An actionable block on the Sampling Customer Tax Compliance screen was implemented as a `UIView` + `UITapGestureRecognizer` with no `accessibilityTraits`. VoiceOver announced only the label — no role. WCAG 4.1.2 requires that the role of interactive components be programmatically determinable.
**Template:** [`WA11Y-IOS-4.1.2-001`](../catalyst-templates/ios/WA11Y-IOS-4.1.2-001.md)

**Bad Code:**
```swift
class TaxComplianceOptionView: UIView {
    override init(frame: CGRect) {
        super.init(frame: frame)
        addGestureRecognizer(UITapGestureRecognizer(target: self, action: #selector(handleTap)))
        isUserInteractionEnabled = true
        // accessibilityTraits not set — VoiceOver: "Accept tax compliance terms"
    }
}
```

**How it was fixed:** Added `isAccessibilityElement = true`, `accessibilityTraits = .button`, and localized label + hint.

**Corrected Code:**
```swift
isAccessibilityElement = true
accessibilityTraits = .button
accessibilityLabel = NSLocalizedString("Accept tax compliance terms", comment: "")
accessibilityHint = NSLocalizedString("Confirms your tax compliance agreement", comment: "")
// VoiceOver: "Accept tax compliance terms, button"
```

### Example: UICollectionViewCell option missing .button trait (Cart V2 Protection Plan) (CEPG-339158)

**What failed:** `UICollectionViewCell` subclasses as selectable Protection Plan tier options had `isAccessibilityElement = true` and a label, but no `.button` trait. VoiceOver announced the label only — no role or selection state.
**Template:** [`WA11Y-IOS-4.1.2-001`](../catalyst-templates/ios/WA11Y-IOS-4.1.2-001.md)

**Bad Code:**
```swift
accessibilityLabel = plan.displayName
// accessibilityTraits implicitly .none — no .button
```

**How it was fixed:** Overrode `accessibilityTraits` getter to compose `.button` + `.selected`.

**Corrected Code:**
```swift
override var accessibilityTraits: UIAccessibilityTraits {
    get { isSelected ? [.button, .selected] : .button }
    set { super.accessibilityTraits = newValue }
}
// VoiceOver: "Basic protection plan, selected, button"
```

### Example: Aisle info button not focusable — UIView with dynamic numeric label (CEPG-283455)

**What failed:** On the Unified Delivery ILC "How do you want your items" screen (No Intent selected), an "Aisle \<number\>" button was a custom `UIView` with no `isAccessibilityElement = true`. VoiceOver skipped it entirely — the aisle location was invisible to AT users.
**Template:** [`WA11Y-IOS-4.1.2-001`](../catalyst-templates/ios/WA11Y-IOS-4.1.2-001.md) — Var 3

**Bad Code:**
```swift
func configure(aisleNumber: Int) {
    aisleLabel.text = "Aisle \(aisleNumber)"
    // ❌ isAccessibilityElement not set — VoiceOver skips entirely
}
```

**How it was fixed:** Set `isAccessibilityElement = true`, `accessibilityTraits = .button`, and a dynamic `accessibilityLabel` built from the data-model integer.

**Corrected Code:**
```swift
func configure(aisleNumber: Int) {
    aisleLabel.text = "Aisle \(aisleNumber)"
    isAccessibilityElement = true
    accessibilityTraits = .button
    accessibilityLabel = NSLocalizedString(
        "Aisle \(aisleNumber)",
        comment: "In-store aisle location for this item"
    )
    // VoiceOver: "Aisle 7, button" ✅
}
```

### Example: Purchase History Disclaimer button not in accessibility tree + bottomsheet focus transition (AMENDS-878)

**What failed:** On the iOS Purchase History screen (Order Totals section), a "Disclaimer" button below ads was a custom `UIView` with no `isAccessibilityElement = true`. VoiceOver skipped it. The fix also required managing VoiceOver focus when the legal info bottomsheet was presented and dismissed.
**Template:** [`WA11Y-IOS-4.1.2-001`](../catalyst-templates/ios/WA11Y-IOS-4.1.2-001.md) — Var 5

**Bad Code:**
```swift
// disclaimerButtonView: UIView — no accessibility properties, no focus management
// VoiceOver: skips entirely
```

**How it was fixed:** `isAccessibilityElement = true` + `.button` trait + `accessibilityLabel = "Disclaimer"`, plus `UIAccessibility.post(.screenChanged, ...)` on bottomsheet open and dismiss.

**Corrected Code:**
```swift
// Make button accessible
disclaimerButtonView.isAccessibilityElement = true
disclaimerButtonView.accessibilityTraits = .button
disclaimerButtonView.accessibilityLabel = NSLocalizedString("Disclaimer", comment: "")
// VoiceOver: "Disclaimer, button" ✅

// On bottomsheet present — move focus in
UIAccessibility.post(notification: .screenChanged, argument: sheet.titleLabel)

// On bottomsheet dismiss — return focus to trigger
UIAccessibility.post(notification: .screenChanged, argument: disclaimerButtonView)
```

### Example: Auto Care Center chevron button skipped by VoiceOver — contextual composite label required (CEPG-296539)

**What failed:** On the Auto Care Center page (Services), a Chevron `>` disclosure button alongside "Your service is on hold" text was implemented as a `UIImageView`/`UIView` with no `isAccessibilityElement = true`. VoiceOver skipped it entirely — screen reader users could not navigate to the service detail view. The fix also required a composite label that combined action + vehicle context + status, since the chevron icon alone conveys no meaning.
**Template:** [`WA11Y-IOS-4.1.2-001`](../catalyst-templates/ios/WA11Y-IOS-4.1.2-001.md) — Var 4

**Bad Code:**
```swift
// chevronImageView: UIImageView — no accessibility properties set
// VoiceOver: skips it entirely
```

**How it was fixed:** Set `isAccessibilityElement = true`, `accessibilityTraits = .button`, and a composite `accessibilityLabel` combining action verb + vehicle name + status from surrounding UI.

**Corrected Code:**
```swift
chevronImageView.isAccessibilityElement = true
chevronImageView.accessibilityTraits = .button
chevronImageView.accessibilityLabel = NSLocalizedString(
    "Show details. \(service.vehicleName). \(service.statusText)",
    comment: "Chevron button to view Auto Care service details"
)
// VoiceOver: "Show details. Auto Service For TOYOTA TUNDRA. Your service is on hold, button" ✅
```

### Example: FAQ header missing expanded/collapsed state in VoiceOver (CEPG-296542)

**What failed:** ACC Digital CAF FAQ section headers used custom `UIView` subclasses. Expand/collapse taps changed content but VoiceOver announced only the label — state was invisible.
**Template:** [`WA11Y-IOS-4.1.2-003`](../catalyst-templates/ios/WA11Y-IOS-4.1.2-003.md)

**Bad Code:**
```swift
var isExpanded: Bool = false {
    didSet { updateContent() }
}
// accessibilityTraits and accessibilityValue never set
```

**How it was fixed:** Set `isAccessibilityElement = true`, `accessibilityTraits = .button`, `accessibilityValue = "collapsed"` on init, and updated `accessibilityValue` + posted `.layoutChanged` in `didSet`.

**Corrected Code:**
```swift
override init(frame: CGRect) {
    super.init(frame: frame)
    isAccessibilityElement = true
    accessibilityTraits = .button
    accessibilityValue = "collapsed"
}
var isExpanded: Bool = false {
    didSet {
        updateContent()
        accessibilityValue = isExpanded ? "expanded" : "collapsed"
        UIAccessibility.post(notification: .layoutChanged, argument: self)
    }
}
// VoiceOver: "How do I cancel my subscription?, collapsed, button"
```

### Example: Button silenced by over-grouping container — not activatable (PGSPHARM-59761)

**Feature:** Pharmacy Preference Center delivery row
**Ticket:** PGSPHARM-59761 / PR #43278

**What failed:** Row container had `isAccessibilityElement = true` with a composite `accessibilityLabel = "Orange Garden, Switch On, View Authorization"`. VoiceOver read the combined string but double-tapping activated nothing — the "View Authorization" `UIButton` was invisible to VoiceOver and the container had no `accessibilityActivate()` override.

**Template:** [`WA11Y-IOS-4.1.2-004`](../catalyst-templates/ios/WA11Y-IOS-4.1.2-004.md)

**Bad Code:**
```swift
isAccessibilityElement = true
accessibilityLabel = "\(person.name), Switch On, View Authorization"
// Double-tap: nothing — viewAuthButton is hidden from accessibility tree ❌
```

**Fix:** Remove `isAccessibilityElement = true` from container; use `accessibilityElements` to expose switch and button independently:
```swift
isAccessibilityElement = false
deliverySwitch.accessibilityLabel = "Enable delivery for \(person.name)"
viewAuthButton.accessibilityLabel = "View Authorization for \(person.name)"
accessibilityElements = [deliverySwitch, viewAuthButton]  // ✅ each fully operable
```

### Example: Inline paragraph link not individually focusable — CCPA "Privacy Notice" (CECPRO-31015)

**Feature:** GPC CCPA Opt-out confirmation screen — "Privacy Notice" embedded in paragraph text
**Ticket:** CECPRO-31015 / PR #145602
**Template:** [`WA11Y-IOS-4.1.2-005`](../catalyst-templates/ios/WA11Y-IOS-4.1.2-005.md)

**What failed:** The CCPA "Opt-out Request Honored" paragraph was implemented as a `UILabel` with `isAccessibilityElement = true` and the full text as `accessibilityLabel`. VoiceOver read the entire paragraph as one stop — "Privacy Notice" was audible but could not receive independent focus, had no `.link` role announced, and double-tapping did nothing.

**Bad Code:**
```swift
bodyLabel.isAccessibilityElement = true
bodyLabel.accessibilityLabel = "By submitting this request, you're opting out of the sale and sharing of your personal information. For more details, see our Privacy Notice."
// VoiceOver: reads full paragraph — "Privacy Notice" inactivatable ❌
```

**How it was fixed:** Registered the link as a `UIAccessibilityCustomAction` on the label element. VoiceOver users discover it via the Actions rotor (swipe up while focused).

**Corrected Code:**
```swift
bodyLabel.isAccessibilityElement = true
bodyLabel.accessibilityLabel = NSLocalizedString(
    "By submitting this request, you're opting out of the sale and sharing of your personal information. For more details, see our Privacy Notice.",
    comment: "CCPA opt-out confirmation paragraph"
)
bodyLabel.accessibilityCustomActions = [
    UIAccessibilityCustomAction(
        name: NSLocalizedString("Open Privacy Notice", comment: "VoiceOver action to open privacy notice"),
        target: self,
        selector: #selector(handlePrivacyNoticeTap)
    )
]

@objc private func handlePrivacyNoticeTap() -> Bool {
    onPrivacyNoticeTapped?()
    return true
}
// VoiceOver: paragraph read → user swipes up on rotor → "Open Privacy Notice" → double-tap opens link ✅
```

**Alternative (multiple links):** Use `UITextView` with `isEditable = false`, `isSelectable = true`, and `NSLinkAttributeName` — VoiceOver independently focuses each link with automatic "link" role announcement.

## Example: Frames iframe is missing a title attribute

**What failed**: Iframes need a title attribute for screen readers to explain their content.

**Bad Code**:
```html
    <iframe height="100" src="../example-pages/demo.html" width="300"></iframe>
```

**How it was fixed**: Applied semantic HTML rule.

**Corrected Code**:
```html
    <iframe height="100" src="../example-pages/demo.html" width="300" title="Embedded Content"></iframe>
```
