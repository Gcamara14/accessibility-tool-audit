## iOS Examples

### Example: Survey buttons focusable but not activatable — VoiceOver double-tap does nothing (LD-6830)

**Feature:** Delivery Survey answer selection
**Ticket:** LD-6830 / PR #121773
**Template:** [`WA11Y-IOS-2.1.1-001`](../catalyst-templates/ios/WA11Y-IOS-2.1.1-001.md)

**What failed:** Survey answer buttons used a `UILongPressGestureRecognizer` as their only activation mechanism. VoiceOver announced each button correctly, but double-tapping did nothing — VoiceOver's double-tap dispatches a tap event, not a long press. Even without AT, users had to press-and-hold to activate, confirming the long-press-only implementation.

**Bad Code:**
```swift
let longPress = UILongPressGestureRecognizer(target: self, action: #selector(handleLongPress(_:)))
longPress.minimumPressDuration = 0.3
addGestureRecognizer(longPress)
isAccessibilityElement = true
accessibilityTraits = .button
// VoiceOver: focuses button, announces "button" — double-tap fires nothing ❌
```

**How it was fixed:** Replaced with `UIButton` using `.touchUpInside` — VoiceOver's double-tap natively fires this action. Added `.selected` trait to announce which answer is currently active.

**Corrected Code:**
```swift
let button = UIButton(type: .system)
button.addTarget(self, action: #selector(handleTap), for: .touchUpInside)
button.accessibilityTraits = isSelected ? [.button, .selected] : .button
// VoiceOver: double-tap → action fires → .selected announced ✅
```

**Alternative (keep custom view):** Override `accessibilityActivate()` to bridge VoiceOver's double-tap into the existing handler:
```swift
override func accessibilityActivate() -> Bool {
    activate()  // same handler used by long-press path
    return true
}
```

### Example: W+ MPS nudge "Make your pick" — button announced but double-tap does nothing (CEWMPLUS-136173)

**Feature:** Walmart+ Membership Hub — MPS (Membership Plan Selection) nudge CTA
**Ticket:** CEWMPLUS-136173 / PR #139408
**Template:** [`WA11Y-IOS-2.1.1-001`](../catalyst-templates/ios/WA11Y-IOS-2.1.1-001.md) — Var 2

**What failed:** The "Make your pick" CTA on the W+ MPS nudge was exposed as a button (VoiceOver announced "Make your pick, button") but double-tapping produced no action. The action handler was attached to a parent container view — not to the accessible element itself — making it unreachable via VoiceOver's double-tap dispatch path.

**Bad Code:**
```swift
ctaLabel.isAccessibilityElement = true
ctaLabel.accessibilityTraits = .button
// ❌ Tap recognizer on parent — not fired when VoiceOver double-taps ctaLabel
parentView.addGestureRecognizer(UITapGestureRecognizer(target: self, action: #selector(didTapCTA)))
```

**How it was fixed:** Replaced the `UILabel` + parent gesture recognizer with a `UIButton` whose `.touchUpInside` target is set directly — VoiceOver's double-tap fires this natively.

**Corrected Code:**
```swift
let ctaButton = UIButton(type: .system)
ctaButton.setTitle("Make your pick", for: .normal)
ctaButton.accessibilityLabel = NSLocalizedString("Make your pick", comment: "")
ctaButton.addTarget(self, action: #selector(didTapCTA), for: .touchUpInside)
// VoiceOver: "Make your pick, button" → double-tap → action fires ✅
```

**Alternative (keep UILabel/custom view):** Override `accessibilityActivate()` on the accessible element:
```swift
override func accessibilityActivate() -> Bool {
    onMakeYourPick?()
    return true
}
```

## Example: Link acting as a button fails spacebar activation

**What failed**: Native buttons trigger on space and enter. Links with role="button" require custom JS for spacebar. Prefer native <button>.

**Bad Code**:
```html
<a class="button" href="next.html" role="button">Continue</a>
```

**How it was fixed**: Applied the correct semantic fix.

**Corrected Code**:
```html
<button class="button" onclick="window.location='next.html'">Continue</button>
```
