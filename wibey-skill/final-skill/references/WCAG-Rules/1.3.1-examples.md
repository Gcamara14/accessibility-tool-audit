## Example: Empty heading tag

**What failed**: Empty headings create confusion for screen reader users navigating by headings, as they hear a heading level but no content.

**Bad Code**:
```html
<h4></h4>
<p>This paragraph is preceded by an empty H4</p>
```

**How it was fixed**: Applied the correct fix based on the component type.

**Corrected Code**:
```html
<h4>Section Title</h4>
<p>This paragraph is preceded by an empty H4</p>
```

## iOS Examples

### Example: Split labels for "Free items remaining: X" not grouped for VoiceOver (GPUGC-23161)

**What failed:** Two sibling `UILabel` instances — `"Free items remaining:"` and `"\(count) items"` — were each independently accessible. VoiceOver announced them as separate focus stops, fragmenting the semantic statement.
**Template:** [`WA11Y-IOS-1.3.1-001`](../catalyst-templates/ios/WA11Y-IOS-1.3.1-001.md)

**Bad Code:**
```swift
let titleLabel = UILabel()  // "Free items remaining:"
let countLabel = UILabel()  // "3 items"
containerView.addSubview(titleLabel)
containerView.addSubview(countLabel)
```

**How it was fixed:** Parent container made the sole accessibility element with a computed combined `accessibilityLabel`, refreshed on every count change.

**Corrected Code:**
```swift
titleLabel.isAccessibilityElement = false
countLabel.isAccessibilityElement = false
containerView.isAccessibilityElement = true
containerView.accessibilityLabel = "Free items remaining: \(freeItemCount) items"
// Recomputed every time freeItemCount changes
```

### Example: Plan card sub-labels not grouped — "Details" button silenced (CEPG-330737)

**What failed:** PHTS "Select Plan" card had `isAccessibilityElement = true` on the root view, collapsing plan name/price/features AND the "Details" button into one opaque stop. The "Details" button became completely inaccessible to VoiceOver.
**Template:** [`WA11Y-IOS-1.3.1-001`](../catalyst-templates/ios/WA11Y-IOS-1.3.1-001.md)

**Bad Code:**
```swift
isAccessibilityElement = true
accessibilityLabel = "Basic $9.99/mo Covers up to 3 devices"
// "Details" button: unreachable
```

**How it was fixed:** Used `accessibilityElements = [summaryContainerView, detailsButton]` to expose exactly two stops while preserving the interactive button.

**Corrected Code:**
```swift
isAccessibilityElement = false
summaryContainerView.isAccessibilityElement = true
summaryContainerView.accessibilityLabel = "Basic, $9.99 per month. Covers up to 3 devices. Cancel anytime."
accessibilityElements = [summaryContainerView, detailsButton]
```

### Example: UITableViewCell sub-labels not grouped (protection plan row) (CEPG-330734)

**What failed:** `UITableViewCell` with four child `UILabel`s (`planNameLabel`, `monthlyPriceLabel`, `coverageDescriptionLabel`, `termLabel`) — all independently focusable. VoiceOver produced four unrelated stops per row with no indication they described one plan.
**Template:** [`WA11Y-IOS-1.3.1-001`](../catalyst-templates/ios/WA11Y-IOS-1.3.1-001.md)

**Bad Code:**
```swift
// No accessibility configuration — four labels independently focusable
final class ProtectionPlanCell: UITableViewCell {
    let planNameLabel = UILabel()
    let monthlyPriceLabel = UILabel()
    let coverageDescriptionLabel = UILabel()
    let termLabel = UILabel()
}
```

**How it was fixed:** Overrode `accessibilityLabel` on the cell to compose a single natural sentence; child labels set to `isAccessibilityElement = false`.

**Corrected Code:**
```swift
override var accessibilityLabel: String? {
    get {
        return "\(planNameLabel.text ?? "") plan. \(monthlyPriceLabel.text ?? ""). " +
               "\(coverageDescriptionLabel.text ?? ""). \(termLabel.text ?? "")."
    }
    set { super.accessibilityLabel = newValue }
}
// All child labels: isAccessibilityElement = false
```
